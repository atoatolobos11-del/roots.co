# ROOTS.CO — Modern Fashion E-Commerce UI

A responsive fashion e-commerce interface built with **React**, **Node.js** and **Tailwind CSS**,
created as a portfolio project. It features reusable product components, category filtering,
wishlist and cart interactions, responsive navigation and a premium editorial shopping experience.

Photography is **CC0 1.0** (public domain) sourced through the Openverse API and curated by
reviewing every candidate; see [CREDITS.md](CREDITS.md) for per-file provenance. Everything else
under `public/images/` is original vector artwork generated by `scripts/generate-assets.mjs`. No
third-party or copyrighted photography is used or bundled.

## Quick start

```bash
npm install
npm run dev        # http://localhost:5173
```

| Script                    | What it does                                            |
| ------------------------- | ------------------------------------------------------- |
| `npm run dev`             | Vite dev server with HMR                                 |
| `npm run build`           | Regenerates the artwork, then bundles to `dist/`         |
| `npm run preview`         | Serves the production build locally                      |
| `npm run lint`            | oxlint over `src/` and `scripts/`                        |
| `npm run test:smoke`      | Server-renders every component + asset/a11y assertions  |
| `npm run test:account`    | Account dialog ARIA wiring + field validation rules     |
| `npm run test:account:flow` | Drives the account flow in headless Chromium (needs `npx playwright install chromium`) |
| `npm run audit:links`    | Fails on any button without a handler or a link pointing nowhere |
| `npm run test:interactions` | Clicks every control and asserts each one does something observable |
| `npm run generate:assets` | Redraws the vector art in `public/images` and `public/og-image.png` |
| `npm run fetch:photos`    | Re-fetches the CC0 photography into `public/images/photos`  |

## Design system

The palette is warm and tonal, matched to the photography (cream, camel, tan leather, denim)
rather than the cool greys a neutral fashion site defaults to.

| Token           | Value     | Use                                  |
| --------------- | --------- | ------------------------------------ |
| `ink`           | `#1C1917` | Espresso — buttons, type, dark surfaces |
| `soft`          | `#332E2A` | Hover state for dark surfaces        |
| `off`           | `#F8F5EF` | Warm off-white — image placeholders, hover fills |
| `mist`          | `#EDE7DC` | Sand — skeletons, image boxes        |
| `ash`           | `#7A7267` | Secondary text                        |
| `line`          | `#DDD5C7` | Hairline borders                      |
| `accent`        | `#A98A62` | Camel accent — used sparingly (sale nav, hover links) |

Type: **Inter Variable**, self-hosted from `public/fonts` (latin subsets only), weights 100–900.
Content is capped at `max-width: 1440px` with `px-4 / sm:px-6 / lg:px-10` gutters.

Reusable component classes live in `src/index.css`: `.shell`, `.label`, `.label-dark`,
`.btn-dark`, `.btn-light`, `.btn-outline`, `.btn-ghost-light`, `.link-arrow`.

## Features

- **Announcement bar** — thin black bar, rotating messages, reduced-motion aware.
- **Sticky header** — centred desktop nav, slide-in drawer below `lg`, wishlist and bag counters.
- **Hero** — full-bleed art with a left scrim; a separate portrait crop is served to phones via
  `<picture>`, so mobile never crops badly.
- **Benefits strip** — 4 items, 2-up on mobile, 4-up from `md`.
- **Shop by category** — circular tiles, horizontal snap scroll on mobile, sets the grid filter.
- **New Arrivals** — filter chips with live counts, 2/3/4/5/6 column responsive grid, empty states.
- **Product cards** — hover image swap on pointer devices, tap-driven quick add on touch,
  wishlist heart, discount badges, colour swatches, quick-add size row.
- **Promotional row** — three distinct visual treatments, 1/2/3 column responsive.
- **Explore Collections** — snap-scrolling gallery with arrow controls and edge-state detection.
- **Editorial band** — statement + stats + offset imagery.
- **Cart drawer** — per-size line items, quantity steppers, free-shipping progress, subtotal.
- **Checkout** — three steps (contact → delivery → confirmation) with validation, delivery
  options and a live order summary. Placing an order clears the bag. No payment field exists.
- **Help & about dialog** — contact, shipping, returns, FAQ, size guide, stores,
  sustainability, careers and the story, opened from the footer, the promo CTAs and the chat widget.
- **Account dialog** — sign in / create account tabs, inline validation, show-password toggle,
  animated field entrances, and a signed-in summary panel. Reachable from the header icon
  (desktop) or the mobile menu.
- **Wishlist** — toggle hearts, persisted to `localStorage`.
- **Search overlay** — live results across name/category/tags, popular searches, category browse.
- **Support chat widget** — scripted replies, typing indicator, fully keyboard accessible.
- **Back-to-top** — appears after 700px, stacked above the chat launcher.
- **Footer** — dark brand values, link columns, working newsletter form, payment meta.

### Interactions and state

| Requirement | Implementation |
| --- | --- |
| FR-01 Navigation | `Header` / `MobileMenu` / `useShop().applyFilter` + smooth scroll |
| FR-02 Search | `SearchOverlay` + `matchesQuery()` over name, category, tagline, tags |
| FR-03 Wishlist | `WishlistContext` → `useLocalStorage('cstyle.wishlist.v1')` |
| FR-04 Cart | `CartContext` → `useLocalStorage('cstyle.cart.v1')`, lines keyed by id + size |
| FR-05 Category filter | `ShopContext`; `Sale` is derived from discounted products |
| FR-06 Account | `AuthContext` → `localStorage('rootco.session.v1')`, `AccountModal` |
| FR-07 Checkout | `CheckoutContext` + `CheckoutModal`; placing an order clears the cart |

### Every control does something

Two guards keep it that way, both in CI:

- `audit:links` is a static check — no `<button>` without an `onClick` or `type="submit"`, no
  `href="#"`, no hash link to an id that does not exist, and every collection card mapped to a
  real filter.
- `test:interactions` is the behavioural check — it clicks each control in a real browser and
  asserts an observable effect: a dialog opens, the grid filters, the scroll moves, or the bag
  changes. This is what catches a handler wired to the wrong thing, which a static check cannot.

The account and checkout flows are **front-end only**: there is no backend, no order is placed and no
request leaves the browser. Sign-in accepts any well-formed email and derives a display name from
it. Passwords are validated but never stored — only a name, an email and a timestamp are persisted.
Checkout deliberately has no card field; placing an order clears the bag and shows a reference.

## Accessibility

- Semantic landmarks, one `<h1>`, no skipped heading levels (asserted by `test:smoke`).
- Every `<img>` has an `alt`; decorative images use `alt=""` + `aria-hidden`.
- Icon-only buttons carry `aria-label`; toggles expose `aria-pressed`.
- Drawers and overlays are `role="dialog" aria-modal="true"`, trap Tab, close on Escape
  (top-most overlay only) and restore focus to the trigger.
- The account form uses a labelled `role="tablist"` for the sign-in / sign-up switch, links every
  field error with `aria-describedby`, and marks fields `aria-invalid` only when they actually fail.
  Asserted by `test:account` and exercised end-to-end by `test:account:flow`.
- Body scroll locking handles iOS Safari and the scrollbar gutter.
- Visible focus rings on every interactive element, inverted on dark surfaces.
- `prefers-reduced-motion` disables animation and smooth scrolling.

## Performance

- React is code-split into its own chunk; the app payload is ~24 kB gzipped on top of it.
- Photography is pre-cropped to the exact frame each slot renders (4:5 cards, 16:9 hero, 3:2 bands)
  and served as mozjpeg q80, so the browser does no client-side resizing. The whole `public/images`
  tree is ~3.3 MB; the vector art in it is ~340 kB.
- Below-the-fold images are `loading="lazy"` + `decoding="async"`; the hero is `fetchPriority="high"`.
- Inter is self-hosted with only the latin subsets, preloaded in `index.html`.
- No runtime API calls, no external requests, no tracking.

## SEO

Title, description, canonical, Open Graph and Twitter card metadata in `index.html`, plus
`robots.txt` and `sitemap.xml`; semantic headings and descriptive alt text.

The production URL is currently `https://root.co/`. Change it with one command, which rewrites the
canonical, `og:url`, the absolute `og:image` and both SEO files together:

```bash
npm run set:url -- https://your-domain.com
```

`npm run check:url` (add `--strict` to fail) reports any mismatch; CI runs it in strict mode.

## Docker

```bash
docker compose up --build
# → http://localhost:8080
```

A three-stage build: `npm ci` → `npm run build` → nginx serving `dist` with gzip, immutable
caching for hashed assets and fonts, and SPA fallback. Vercel ignores the Docker files entirely
(it uses `npm run build` and `dist`).

## Deployment to Vercel

1. Push the repository to GitHub.
2. Import it at [vercel.com/new](https://vercel.com/new).
3. Framework preset **Vite** · Build `npm run build` · Output `dist` · Install `npm install`.
4. No environment variables are required.

## Licence and originality

All product names, taglines, prices, brand values and imagery in this repository are original and
fictional. The artwork is produced by `scripts/generate-assets.mjs`, which draws flat tonal
